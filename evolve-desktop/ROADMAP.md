# Evolve 후반 산업 확장: 구조 분석과 단계별 구현

기준: Evolve 1.4.10, 공식 소스 커밋 `3436358dcd03d9f9e071d51ea071e0a78c0322e4`.
현재 완료 범위는 **1차 저장 안정화**이며, 2~6차는 아래 설계에 따라 별도로 구현한다.
목표는 생물 진화 → 문명 → 산업화 → 우주 진출을 유지하면서 후반 관리 단위를 시설 → 행성 → 항성계 → 성간 산업망으로 확장하는 것이다.

## 현재 코드의 경계

- 루트의 `app.js`, `engine.mjs`, `desktop.cjs`는 이전 EXO Industries 게임이다. 이번 변경 대상이 아니다.
- `evolve-desktop/main.cjs`는 Electron 창, 로컬 파일 제공, 저장 폴더와 종료 처리를 담당한다.
- `upstream/src/`는 원본 게임 소스, `upstream/evolve/main.js`는 실제 실행되는 원본 번들이다.
- `scripts/prepare-evolve.cjs`가 원본 무결성을 확인하고 오프라인 실행 폴더 `web/`를 생성한다. `web/`를 직접 고쳐서는 변경이 유지되지 않는다.
- 1차는 래퍼만 변경한다. 2차부터는 별도 작업용 소스 복사본에 검토 가능한 패치를 적용하고 원본 `buildEvolve.js` 방식으로 번들을 생성하는 빌드 단계를 먼저 추가한다. 기준 원본과 그 해시는 보존한다. 수정 모듈의 MPL 고지와 소스도 제공한다.

## 파일별 연결 관계

| 시스템 | 원본 파일 (`upstream/src/`) | 역할과 확장 위치 |
|---|---|---|
| 상태·호환성 | `vars.js` | `global` 상태, 기존 저장 로드, 버전 마이그레이션. 새 필드는 없는 경우만 초기화한다. |
| 게임 루프·생산·저장 | `main.js` | 빠른/중간/긴 주기, 전력·지원량·연료에 따른 실제 가동 수, 자원 생산, 약 5초 자동저장. 우주 자동화 호출과 생산 항목 연결 지점. |
| 구매·건설 큐 | `actions.js`, `functions.js` | 건물 정의, 비용 지불, 건설 큐·연구 큐. 자동 건설도 같은 해금·비용·큐 한도를 적용한다. |
| 기존 자동화 | `governor.js` | 총독과 작업 실행 조건. 새 자동화가 기존 작업과 같은 시설을 중복 구매하지 않도록 우선순위를 정한다. |
| 우주·성간 | `space.js`, `interstellar.js` | 행성/지역별 시설과 요구 조건. 실제 시설 상태를 기반으로 산업력을 집계한다. |
| 생산 수치 | `prod.js`, `main.js`, `industry.js` | 시설별 기본 생산·기존 보정, 실제 생산 합산, 공장·전력. 우주에서 발생한 생산 항목에만 새 승수를 적용한다. |
| 해금 | `tech.js` | 기존 연구 조건과 연결해 목표·자동화를 점진적으로 해금한다. |
| 리셋·영구 성장 | `resets.js`, `functions.js`, `vars.js` | MAD/Bioseed/Big Bang 등 서로 다른 리셋 경로, 보상 계산, 다음 문명 상태 구성. 각각 보존 범위를 명시해야 한다. |
| UI·번역 | `index.js`, `space.js`, `strings/` | 산업 관리 패널, 다음 목표, 자동화 이유·대기 이유, 승수 내역을 표시한다. 추가 문구는 별도 이름 공간으로 관리한다. |

`modRes()`는 생산뿐 아니라 소비와 일회성 보상도 처리한다. 여기에 전역 승수를 붙이면 비용·보상까지 바뀌므로 사용하지 않는다. 시설 수 또한 실제 가동 수와 다르다. 산업력 계산에는 전력·연료·지원량을 반영하고, 꺼진 시설을 늘려 무료 승수를 얻지 않도록 한다.

## 1차 — 자동저장 안정화

원본 저장 키 `evolved`, UTF16 압축 형식, 내보내기 Base64 문자열, 프로필 위치를 그대로 유지한다.

- 원본 자동저장을 30초마다 읽어 검증한 뒤 `last-save.txt`와 최근 10개 `backups/save-*.txt`에 저장한다.
- 임시 파일에 쓰고 파일 동기화를 마친 다음 이름을 변경한다. 새 복구 지점을 먼저 확정하므로 최신 파일 교체 실패 시에도 이전 저장과 새 복구 지점을 유지한다.
- 저장 작업은 순차 처리한다. 같은 내용으로 백업 목록을 채우지 않는다.
- 시작 시 게임 코드를 실행하기 전에 저장을 검사한다. 손상/누락과 정상 백업이 발견되면 복구·종료·새 게임을 선택할 수 있다. 자동으로 초기화하거나 과거 플레이로 되돌리지 않는다.
- 복구 전 저장은 `before-recovery-*.json`으로 별도 보관한다. 이 파일은 자동 순환 삭제 대상이 아니다.
- 상단 게임 메뉴에서 수동 백업, 상태 확인, 백업 파일 복구를 제공한다. 실행 중 실패는 제목에 표시하고 종료 시 실패는 계속 플레이/종료 선택을 제공한다.
- 원본 `exportGame()`은 시간 가속 상태를 갱신한다. 주기적 복사는 이 함수를 호출하지 않는다. 정상 종료/수동 백업만 현재 상태를 캡처하고 `geck`/`noexport` 구간에서는 원본이 남긴 마지막 안전한 저장을 사용한다.
- 원본 게임 코드 113개와 기존 게임 밸런스는 변경하지 않는다.

한계: 강제 종료 시 마지막 원본 자동저장 이후의 진행은 잃을 수 있다. 원본 저장까지 손상된 경우 별도 파일 백업 시점으로 복구한다. 기기 고장이나 디스크 전체 손실에 대비하는 외부 백업은 아니다. 형식 검사는 압축/JSON 및 필수 상태 구조를 확인하며 모든 미래 버전 저장의 의미적 유효성을 보증하지 않는다.

## 2차 — 목표로 해금하는 우주 자동화

별도 `spaceIndustry` 모듈에 목표·규칙 정의를 모으고 루프·UI 연결만 기존 파일에 추가한다. 소행성 채굴과 화성 산업 목표부터 시작한다. 아직 도달하지 않은 영역은 자동화하지 않는다. 최초 해금 때는 사용자가 규칙을 켜도록 한다.

규칙: 대상 시설, 우선순위, 자원별 최소 잔고 또는 저장고 비율, 최대 시설 수, 실행 간격. 부족 자원 우선 규칙도 같은 제한을 지킨다. 실제 구매 가능 여부와 비용은 기존 함수에서 다시 확인하며, 지불 후에도 비축량을 남긴다. 한 번의 주기에 실행할 수 있는 구매 수를 제한한다. 전력·지원량 부족, 연구 미해금, 비축량 부족, 큐 포화는 UI에 이유를 보여 준다. 비용을 계산만 하고 상태를 직접 증액하는 방식은 쓰지 않는다.

검증: 우주 이전 무동작, 목표 달성 때 1회 해금, 저장 후 해금 유지, 비용 지불/비축 보존, 총독·큐와 충돌 방지, 재시작 시 중복 구매 방지. 대기 시간이 줄어들고 반복 클릭 수가 감소하는지도 관찰한다.

## 3차 — 우주 생산 승수와 중간 목표

광물/행성/우주 연구 등 생산 범위를 명시한 승수 항목을 정의한다. `기본량 × 기존 보정 × 해당 우주 보정`으로 계산하고 생산 내역에 각 항목을 표시한다. 처음에는 소수의 목표로 적용 범위를 검증한다. 사용자가 예시로 든 x2/x5 등은 목표 감각을 나타내는 후보이며 그대로 전체 자원에 중첩하지 않는다.

검증: 지상 생산·소비·일회성 보상이 바뀌지 않는지, 미해금 승수는 1인지, 해금 전후 표시량과 실제 증가량이 일치하는지, 연료·지원량 병목을 우회하지 않는지. 비용 감소와 연구 효율 보상은 기존 비용·연구 계산 경로에 분리 적용한다.

## 4차 — 행성 산업력

화성·소행성대 등 지역별 실제 가동 시설과 생산 능력으로 집계한다. 시설 종류별 가중치는 데이터 정의로 분리하고, 중복 합산하지 않는다. 해금된 목표는 기록하되 현재 산업력은 파생값으로 재계산한다. 숫자 표시 외에도 행성별 자동 증설 정책을 제공해 관리 단위를 바꾼다. 자급률 목표는 해당 행성의 생산/소비 기여도를 추적한 뒤 추가한다.

검증: 시설 on/off, 연료 고갈, 전력 부족 때 변동, 지역별 귀속, 저장 로드 후 동일 계산, 목표 보상 중복 지급 방지.

## 5차 — 항성계와 성간 산업망

행성 산업력을 항성계로 합산하고, 항성계 목표를 달성하면 생산·연구 보정 및 여러 행성의 증설 정책을 함께 관리할 수 있게 한다. 이후 성간 해금 조건에 맞춰 산업망으로 확장한다. 처음부터 모든 은하·다른 우주의 지역을 한꺼번에 합산하지 않는다.

검증: 지역→행성→항성계의 중복 합산 방지, 미진입 구역 제외, 서로 다른 행성 정책 간 예산 충돌 방지. 목표 1,000/10,000은 시험 플레이 후 확정한다.

## 6차 — 기존 리셋을 살리는 장기 성장

Plasmid/Phage 등 기존 보상 및 챌린지를 유지한다. 새 영구 포인트가 필요하면 뒤늦은 기존 세이브에도 정의된 달성 기록을 근거로 1회만 지급한다. 저장 문자열 재가져오기로 보상을 중복 얻지 않게 기록한다. 행성 단위 해금 기록과 문명 내 정책을 구분하고, 리셋별 보존 표를 만든 뒤 구현한다.

후보 보상: 연구 효율, 비용 완화, 초반 자원, 이미 획득한 자동화의 조기 활성화, 우주 진입 가속. 아직 한 번도 달성하지 않은 우주 목표를 건너뛰게 하는 방식은 피한다. `global`의 새 필드는 초기값과 스키마 버전을 가지며 기존 저장을 원본의 마이그레이션 후 확장한다.

검증: 각 지원 리셋 경로의 포인트 산정/보존/소비, 반복 리셋 중복 지급 방지, 챌린지 보상 제한, 구형 저장과 확장 저장 왕복, 같은 구간의 재진입 시간 비교. 후반 데이터와 실제 플레이를 확보한 다음 보상 규모를 확정한다.
