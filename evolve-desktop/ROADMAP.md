# 우주 산업 확장 구현 구조

현재 버전 **Industry r2**는 요청한 1~6차의 첫 통합 구현입니다. 사용법과 정확한 적용 범위·수치는 [INDUSTRY.md](INDUSTRY.md)에 있습니다.

## 원본 구조와 재사용 지점

| 원본 파일 (`upstream/src/`) | 역할 | 이번 연결 |
|---|---|---|
| `vars.js` | 상태, 저장 로드, 기존 마이그레이션 | 원본 유지. `global.industryExpansion`을 확장 모듈에서 초기화 |
| `main.js` | 생산 루프, 전력/지원량/연료, 자동저장 | 긴 주기에 목표/자동화, 생산·연구 계승, 드로이드 생산 보정, 패널 초기화 |
| `actions.js` | 구매/비용 검사, 건설 후 UI와 콜백 | 원본 함수 재사용. 입력 키에 영향받지 않도록 자동화는 구매 가능성 검사 후 `action`/`postBuild` 실행 |
| `functions.js` | 비용 보정, 자원 변경, 건설 큐 | 지상/우주 비용 함수와 우주 진입 비용 보정에만 연결. `modRes`는 수정하지 않음 |
| `space.js` | 우주·성간·은하 시설 정의와 요구 조건 | 원본 `checkSpaceRequirements`, 시설 `struct`, `support`, `powered`, 건설 함수를 사용 |
| `prod.js` | 시설별 생산 기준 | 목록의 우주 생산 반환값에 보정. `{b,f}` 형태의 기준량/최종량을 함께 보정 |
| `governor.js` | 기존 총독 자동화 | 유지. 추가 자동화는 수동 큐가 비었을 때 제한된 횟수만 실행 |
| `resets.js` | MAD/Bioseed/Big Bang 등 리셋 | 실제 리셋의 13개 보상 경로에 추가 보상 연결. 원본 보상 계산은 유지 |

성간 시설도 이 버전에서는 `space.js` 안에 정의되어 있습니다. 별도 `interstellar.js`를 수정하는 구조가 아닙니다. 루트의 `app.js`와 `engine.mjs`는 과거 EXO 게임이며 변경 대상이 아닙니다.

## 단계별 결과

1. **저장 안정화**: `main.cjs`, `saves.cjs`, `recovery.cjs`에서 주기적 파일 백업, 순환 보관, 원자적 파일 교체, 시작 전 검사, 수동 복구. r1 구현 유지.
2. **우주 자동화**: `mods/industry-runtime.js`에서 원본 구매 경로 연결. `industry-core.mjs`에서 해금·우선순위·비축·정책 관리. 20개 반복 시설의 명시적 목록을 사용하며 임무·리셋·희귀 포인트 구매는 자동화하지 않음.
3. **생산 승수**: 우주 시설 기준 생산량과 드로이드 4종 생산 기여에 적용. 소비·드로이드 배분 수·단발 보상에는 적용하지 않음. UI에 지역/태양계/산업망/계승 승수 표시.
4. **행성 산업력**: 달·화성·소행성대·가스 행성의 실제 가동 수와 가중치를 합산. 행성 단위 정책으로 개별 설정을 한꺼번에 관리.
5. **태양계·성간 산업망**: 태양계 합계 및 알파 센타우리/성운/중성자별 거점 합산. 목표에 따라 더 넓은 정책 범위와 생산 보정 해금.
6. **Prestige 강화**: 기존 리셋 시 문명/항성 포인트 지급, 영구 기술 구매, 다음 문명 보급, 이전 자동화 조기 해금. 챌린지 제한과 시뮬레이션을 고려하고 현재 문명 기록은 리셋.

## 빌드와 저장 경계

원본 113개 파일과 해시는 바꾸지 않습니다. `scripts/prepare-evolve.cjs`가 원본과 외부 라이브러리 무결성을 확인합니다. 이어 `scripts/build-evolve-mod.cjs`가 `build-source/` 복사본에 정확한 문자열 앵커와 개수를 확인하며 패치합니다. 원본이 바뀌어 앵커가 달라지면 빌드를 중단하므로 조용히 잘못된 위치를 고치지 않습니다.

새 모듈은 `industry-core.mjs`(순수 계산·상태), `industry-runtime.js`(원본 함수 연결), `industry-ui.js`/`industry.css`(사용자 화면)로 분리했습니다. 생성물인 `web/`나 원본 `upstream/`를 직접 편집하지 않습니다. 수정 소스와 패치 내역은 소스 아티팩트에 함께 제공합니다.

저장 키와 압축 형식은 유지합니다. 새 상태는 버전 1 이름 공간에만 저장하며 기존 자원과 기술을 일괄 변환하지 않습니다. 산업력은 가동 상태에서 계산하고, 달성 목표/문명 내 최고치와 영구 기술을 구분합니다. 모르는 미래 스키마는 덮어쓰지 않고 확장 기능을 비활성화합니다.

## 검증

- `evolve-assets.test.cjs`: 원본/외부 의존성 무결성, 로컬 파일, 수정 번들·소스 포함.
- `evolve-saves.test.cjs`: 백업·손상·원자적 쓰기 실패·복구 선택.
- `evolve-industry.test.mjs`: 초반 무효과, 실제 가동 수 집계, 목표 1회 지급, 승수, 비축, 자동화 순위·정책, 리셋·포인트·보급·호환성, 13개 리셋 연결.
- `evolve-smoke.cjs`: 실행 파일의 원본 초반 플레이, 한국어, 저장 가져오기, 백업·복구·재시작.
- `evolve-industry-smoke.cjs`: 동일 수정 소스를 테스트 하네스로 묶어 실제 원본 구매·생산 함수, 조건별 자동화 차단, 산업 UI·정책·기술 구매, 원본 MAD 리셋과 저장 재로드 검사. 실제 후반 수십 시간 플레이를 대체한다고 주장하지 않음.

향후 균형 조정은 현재 저장을 유지하면서 목표·가중치·계승 비용을 데이터 정의에서 조정합니다. 자급률 목표와 추가 은하/특수 경로의 산업망 편입은 현재 20개 시설의 실제 플레이 결과를 보고 확장할 수 있습니다.
